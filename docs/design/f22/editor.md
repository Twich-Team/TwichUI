# F22: dispel indicator editor proposal

**Design proposal, not implemented.** The accompanying [library](library.svg), [simple editor](simple.svg), and [advanced editor](advanced.svg) are annotated wireframes, not screenshots or production artwork. They use synthetic characters and states. The visual vocabulary comes from [Settings design system](../../settings-design-system.md), the [Reminders preview and builder](../../reminders-revision/REMINDERS_PREVIEW.PNG), and the [Magic Inventory builder](../../magic-inventory-revision/implementation.md). Runtime support, detection, frame integration, combat behavior and effect semantics must be established by the F22 integration/effects design; these drawings do not assert API availability.

## Player journey and hierarchy

The Settings page opens on a library of indicator designs. A row shows a name, enabled state, short appearance summary and Edit; a context menu offers Duplicate and Delete. New design opens a private draft. Explicit Save commits a valid draft; Cancel discards it. Back or close with changes asks Save / Discard / Keep editing. A disabled or unavailable effect is identified in text, not silently substituted. Deleting a saved design requires a named confirmation; duplicating makes a new disabled draft. Search filters only the library and does not change order or configuration. Empty, no-results and unavailable states explain the next action. The master enable control and any precedence between multiple designs belong to the integration contract, not an implied ordering in these drawings.

The editor uses a fixed heading and footer with a scrollable control area and a persistent preview where space permits. **Simple** presents appearance, placement, size and one animation choice. **Advanced** exposes the same draft through precise numeric fields and effect-specific controls; switching modes never resets or approximates a value. If the draft cannot be represented by Simple controls, show “Custom settings” and retain all values until the player explicitly changes them. Display units, bounds, defaults and available choices from the eventual effect contract; the sample numbers in the drawings are illustrative, not proposed runtime defaults.

## Preview and manipulation

The preview is a deep espresso well with synthetic sample frames, never live unit data or a secure gameplay frame. A Player / Target / Party / Raid selector changes the sample only; it does not change the design's target. The player and target poses each contain one named health bar, party contains five and raid a compact grid. Target includes a hostile sample for purge; friendly samples cover cleanse. Preview one affected sample and unaffected neighbors to reveal density and overlap. Show a labeled “Preview • sample data” badge and a legend for the highlighted sample. A preview state picker includes no indicator, eligible effect, and a non-eligible sample where supported by the integration contract. If a capability is unavailable, label it and explain why; do not imply that the preview establishes game-client support.

Selecting the indicator exposes a clear outline, center anchor and handles. Drag the body to move it relative to the selected frame; drag a corner to resize while preserving aspect ratio. Show live x/y and size values and a ghost of the original position, and clamp to the contract's permitted bounds. End a drag as one undoable edit; Escape cancels the active drag, pointer loss restores its starting value, and releasing outside the well uses the last valid in-bounds position. A click on the background deselects. Do not place a live frame or alter combat UI through this canvas. Preview handles and guides are editor-only. If a particular effect has no movable or resizable geometry, disable its handles and explain the constraint.

Every drag operation has a numeric alternative: focusable X, Y and size fields with labeled units and stepper buttons. Arrow keys nudge the selected indicator by one field step; Shift+Arrow uses ten steps. Focused inputs retain ordinary text navigation. Tab / Shift+Tab reach all controls in a predictable order, Enter commits a valid field, Escape restores that field's previous value, and focus is visible. Invalid or out-of-range text stays visible with an inline explanation; it cannot silently clamp on Save. Undo / Redo are visible buttons and support Ctrl+Z / Ctrl+Shift+Z while the editor has focus; a completed drag, field commit, preset application or control change is one transaction. Undo history is session-local to the draft; Cancel, save and profile change end it. Do not intercept keys while another modal or text composition owns them.

## Animation and accessibility

The preview exposes Play / Pause and Restart. Show the effect at rest, a labeled active animation phase and the end/rest state; the drawings annotate these phases without claiming motion in a static SVG. Animation choices and parameters must come from the effects contract. Pausing freezes only synthetic preview playback, not the saved setting. Respect the game's available reduced-motion setting if one is confirmed: offer a still preview and clearly label it; never infer client support. Provide an explicit still/animation preview toggle regardless. Indicators must remain distinguishable by shape or placement as well as color; focus, selection, disabled, error and active states also use text or relief, not color alone. Labels and values stay native text in implementation, with tooltips supplementing rather than replacing labels.

## Layout and states

At a wide settings shell, controls occupy the left column and preview the right. At constrained widths, stack controls above preview; keep Save / Cancel in a fixed footer and scroll the body, with no horizontal clipping. Use the existing Settings shell, walnut panels, recessed fields, selection relief and bronze borders; gold is reserved for Save. Maintain the existing 32-unit control rhythm and use concise labels; allow text to wrap with localization. An inline validation summary links or focuses the first problematic control. Preserve scroll/focus when switching modes when possible; never hide an error in the inactive mode. Modal confirmation returns focus to its invoking control. Opening, closing or cancelling a draft must not alter saved settings; only a successful Save changes them. Profile changes must discard the old profile's draft with an explicit notice, rather than writing it into the new profile.

## Implementation and verification boundary

This is design evidence only: no runtime, production art, saved-data schema or gameplay APIs are supplied. Before implementation, resolve supported frame targets, effect availability and bounds against the Forever client and integration contract; enforce combat restrictions centrally. Verify draft save/cancel, mode round-trip, keyboard and pointer parity, undo grouping, validation, unavailable effects, profile changes and narrow layout with focused tests. Review actual client visuals and input separately; SVGs are neither screenshots nor client validation.

## Scope alignment: simple and layered editing

Simple starts with a preset, then offers Player, Target, Party and Raid location choices, eligible types, colors and intensity before Save. These locations are configuration, distinct from the Player / Party / Raid sample selector. Friendly cleanse and hostile purge are separate contexts; eligibility is **yes**, **no**, or **unknown**, never inferred from a missing signal. Detection and target availability remain unverified gates and unavailable choices explain the limitation. Presets are starting points; changes produce a custom draft.

Advanced edits an ordered layer stack. Its palette offers tint, border, icon, artwork, glow, highlight and particle group; drag a palette item into the stack or use Add layer. Select a layer to edit its properties, drag or use fields to move and resize it, and reorder via drag or Move up / Move down buttons. Duplicate and Delete act on the selected layer; named designs can be duplicated or deleted from the library, and templates create drafts. Show the selected layer in both stack and canvas; visible controls and keyboard alternatives provide equivalent operations. A dropped palette item is one undo transaction; reordering, duplication and deletion each create one transaction. Deleting a layer is undoable before Save. All previews use simulated conditions and update as the draft changes.

The proposed safety budget is at most **6 layers per binding**, **16 regions per binding including at most 4 particles**, **64 bindings globally**, **64 particles globally**, and **8 animated bindings**; any remaining bindings stay static. Preview obeys the same budgets and reports when a limit prevents an addition or animation. These are design limits to validate in the effects contract, not claims about the current client. Initial safe designs prefer an outer border or icon and reserve the frame's text zone. The canvas must show reserved areas and reject or explain unsupported placements rather than obscure health/name text by default.

## Reference geometry and illustrative timeline

The 1200 × 760 wireframes are representative design proportions, not client captures. Their 1160 × 720 outer shell has 30-unit side insets, a 70-unit header and 50-unit footer; the editor body uses a 554-unit control column, 42-unit gutter and 480-unit preview. Target a 960 × 620 minimum shell: below 1100 units wide, stack controls and preview in a single vertical scroller, retaining the footer. Minimum interactive controls are 32 units high; use 16-unit section spacing and 12-unit field gaps. These dimensions are design targets subject to actual Settings scale and localization, not existing runtime guarantees.

The Advanced drawing selects an **icon** layer, with a square selection rectangle, corner handle and center anchor; its X/Y/size fields refer to that same icon. The layer list's up/down, Duplicate and Delete buttons are directly visible, and the marked palette drop target also has an Add layer button as its keyboard alternative. Layer order runs top to bottom in rendering order; the final layer is drawn above earlier layers. Properties include color, texture, opacity, placement, size and animation where applicable; unsupported properties are disabled with a reason. The preview condition selector independently chooses friendly cleanse or hostile purge and eligibility yes/no/unknown.

An illustrative pulse timeline starts at rest at **0 ms**, rises to full emphasis at **120 ms**, returns to rest at **800 ms**, and leaves a **150 ms** rest interval before repeating at 950 ms. Play/Pause freezes synthetic playback; Restart returns to 0 ms. These values illustrate the diagram, not established effect defaults or API behavior. A still preview displays the rest state and preserves saved animation settings.
