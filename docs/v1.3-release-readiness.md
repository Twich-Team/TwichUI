## Experimental setting and data policy

The control lives in Settings → Workshop → General. Enabling permits explicit
Load options/Open Workshop actions; it does not eagerly deserialize market data.
The older separate login-loading preference stays optional and is respected only
while Workshop is enabled. Disabling immediately closes Workshop/compact/preview
windows, cancels planning/bridge work and pending login loading, stops observers
and scan controls, and makes installed tooltip hooks inert. An atomic local scan
save already committing is allowed to finish; it is never cut off halfway.
Re-enabling reuses existing frames/hooks. Reloading is optional for unloading
resident code and SavedVariables from memory; it never happens automatically.

The intended policy is conservative: new installations default off. An explicit
older `ui.workshopLoadOnLogin=true` establishes prior enablement; saved recipes,
queues or history alone do not establish intent. An explicit new false setting
must override any older login preference. No saved Workshop records are removed.
The new boolean is `TwichUIDB.ui.workshopEnabled`, scoped to each profile.
Migration runs after profile selection, only fills a missing key and is repeatable.
Profiles not currently selected migrate when applied; future-schema held main
SavedVariables are not changed. Existing manual users with no explicit login
preference conservatively remain off and can enable without losing any data.

Unit-tested: deterministic fresh/disabled/enabled/malformed fixtures, explicit
false precedence, unchanged complete Workshop/local-market fingerprints, simulated
reload/profile transitions, delayed login cancellation, real TOC service stop /
restart and frame/hook reuse. Simulator-tested: the filled Settings flow passed
45 checks plus 22 Home checks with
`SIMLAB_EXTRA=TwichUI_Workshop SIMLAB_SETTINGS_FILLED=true bash tools/simlab/run.sh settings workshop`.
Earlier captures omitted the companion folder; their missing-addon failures remain
preserved. A repeat with next-frame settling alone did not resolve that staging
problem. No production exception or assertion was weakened.

Lifecycle counters and timing remain covered by the existing Workshop load/read /
bank/worth scopes and event gauges; the launcher snapshot now includes enablement.
No new recurring profiling operation or cache was introduced.

The read transport's eight core event listeners also unregister while disabled;
re-enabling registers each once and requires a fresh auctioneer context before
any independently opted-in experimental read. Workshop opt-in never grants that
separate developer capability. Seven focused opt-in mutants and both existing
automatic-scan policy mutants were detected. All 371 mutation definitions validate.
The two auto-scan mutation anchors were updated for the added experimental gate;
their original defect models and assertions were preserved.

Native Blizzard Auction House remains the default. The five-page standalone
preview does not authorize transactions or replacement. Manual local scans and
optional external schema 1/2/3 history remain separate; missing prices are
unknown, and outside-scope records are not absent records. Canonical pricing and
conservative Item Advisor behavior are unchanged.

## Owner checkout and real-client acceptance

Perform these steps only after the final branch table records successful
certification and integration. Use a disposable/test profile where practical.

1. Fetch, then check out `release/v1.3` normally. Update it with
   `git pull --ff-only origin release/v1.3`; do not reset a dirty checkout.
   Compare `git rev-parse HEAD` with PR #27's merge commit or the final campaign report.
2. Build with the documented pinned packager process in `RELEASING.md`, or use
   the locally validated candidate archive identified in the final evidence.
   Do not push a release tag or run the publishing workflow to obtain a build.
3. With the game closed, back up the entire WTF SavedVariables directories,
   including account/character `TwichUIDB` and `TwichUIWorkshopDB`, before the
   owner installs the candidate. The agent does not edit the owner's install or
   real SavedVariables.
4. Log into WoW Forever. Check ordinary TwichUI behavior, navigation, Reminders,
   Settings, bags and existing preferences before enabling Workshop.
5. Open TwichUI Settings → Workshop and inspect **Workshop — Experimental**.
   A fresh profile should show Off. Test a deliberately enabled existing profile
   separately and verify its established intent is retained.
6. Enable Workshop, then inspect professions/known recipes, Crafting plans,
   Shopping and Item Advisor. Verify existing queues, reservations, keep
   priorities, vendor safeguards and saved preferences.
7. Open local Market history. With no external addon, confirm a clear unavailable
   state. With an intentionally installed compatible generation, explicitly open
   external history and check source identity, exact variant, scope and sparse
   data wording. Verify local scans/history remain independent.
8. Open `/tui ahpreview` and inspect Browse, Shopping, Sell preparation, Owned
   and Market. Confirm live buying/bidding/posting/cancel/repost actions remain
   unavailable. Confirm Blizzard's ordinary Auction House is still available
   and remains the default; previewing must not replace it.
9. Reload explicitly, then switch profiles and verify the opt-in, login loading,
   tooltip choices, plans, shopping state and histories persist as intended.
10. Disable Workshop, check that its windows/observers stop, then re-enable it.
    Confirm all saved data remains. Reload explicitly to unload resident code
    and market SavedVariables. No automatic reload or external delivery occurs.
11. Check normal and small windows, long names, empty/loading/error states,
    scrolling/selection preservation, native fonts/localized wrapping, real
    pointer/keyboard focus and Escape. Observe Lua errors, taint, frame time and
    interaction with the owner's other addons.
12. Record defects with reproduction steps before authorizing publication.

The branch for continued Workshop development is `feature/workshop`, after its
mandatory synchronization from the finalized main baseline.
