# Batch 12 merchant quote capture

`merchant.png` is a structural, synthetic simulator capture at runtime source
`9467adb`, not a live merchant or successful purchase. Screenshot-reviewed:
material names, need/stock/quoted quantity, per-purchase bundle price, exact total
copper, insufficient-money disclosure, read-only guidance and Close/Refresh fit
in the compact leather panel. The first three rows and scroll rail are visible.
Game item icons/coin textures are missing and fonts are fallbacks in cloud mode;
this cannot establish native appearance, item contrast or actual input.

The existing Crafting fixture was generated by `tools/simlab/run.sh workshop`
with `SIMLAB_ONLY='craft ...'`, `SIMLAB_ASSETS=0`. A final step was inserted
immediately before `Lab.Finish()` in that **ignored disposable fixture only**:

```lua
Lab.Step("Batch 12 live read-only merchant quote", function()
    local W = TwichUI.Workshop
    local originalGUID = UnitGUID
    MerchantFrame = { IsShown = function() return true end }
    UnitGUID = function(unit)
        if unit == "npc" then return "Creature-0-1-1-1-3333-0000000001" end
        return originalGUID(unit)
    end
    local buys = 0
    BuyMerchantItem = function() buys = buys + 1; error("quote must never purchase") end
    W.MerchantReview.Refresh(true)
    Lab.Settle(1)
    W.MerchantReview.Refresh(true)
    Lab.Check("display", "live quote is visible", true, W.MerchantReview.Stats().shown)
    Lab.Check("state", "quote makes no purchase calls", 0, buys)
    Lab.Settle(.5)
end)
```

No production or simulator source was patched. Names, item qualities, bag counts
and merchant listings come from the existing deterministic scenario. The fixture
uses common materials; it does not establish multi-quality visual fidelity.
The quote displayed **25 copper for one Coarse Thread**, with unavailable
materials explicitly unquoted. Native GetMoney's synthetic zero produces the
insufficient-money label. The actual quote/UI code, ShoppingPlan and merchant
reader ran; no transaction or purchase completion was simulated.

The existing sandboxed `tools/simlab/sim.sh` launched the prepared worker root
with `--no-saved-vars --exec-lua @<disposable fixture> screenshot --png`,
1600×1200. Result: **31 steps, 535 passed, zero failed, no abort**, quote visible,
zero purchase calls. Existing `known_failures.classify` reported zero unknown or
unexpected errors, allowing only the same voice-settings/UTF-8 rules as the
Workshop catalog. Those simulator errors remain in the log; this is not a clean
native-client run. [Combined verification](../../workshop/batch12-verification.md).
