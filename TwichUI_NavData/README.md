# TwichUI Navigation Data

The walking maps TwichUI's navigation plans routes on. Load on demand: TwichUI loads it the first time you plan a route,
never at login and never in combat. Keep it turned on alongside TwichUI if you use navigation; nothing else needs it.

Generated by TwichUI's own tool (`tools/navbake` in the TwichUI repository) from the game client's terrain, buildings,
doodads and liquids, using Recast (zlib licence) offline. The data is derived from Blizzard Entertainment's game data and
is not covered by TwichUI's MIT licence. No data from another addon is included.

## Format (version 2)

`Data/Map<m>.lua` sets `TwichUI.NavDataStore.graph[m]`; `Data/Map<m>_<n>.lua` fill `TwichUI.NavDataStore.tiles[m]["x_y"]`.
Each value is Base64 of zlib-compressed CBOR, decoded by the client's `C_EncodingUtil` (`Enum.CompressionMethod.Zlib`).

- Graph (`Data/Map<m>.lua`, `TwichUI.NavDataStore.graph[m]`): `f` format, `cells` per tile side, `n` crossings (tile x, tile y,
  polygon, other tile x, y, polygon, x·10, y·10, z), `af` and `ad` the edges between crossings inside a tile as an adjacency
  list: crossing c's edges are `ad[af[c]]` to `ad[af[c + 1] - 1]`, both directions stored, each one number,
  neighbour + 16384 · (cost + 8192 · tile x·64 + y), so a decoded array is the runtime structure as it is. The edges are a
  5% spanner of every pair inside each tile (every path is at most 5% longer than over all pairs, and nothing is
  disconnected). `k` each crossing's component, `ca` and `cg` each component's walkable and ground area in square yards,
  `t` tiles, `factor` the area costs (ground, water, ocean).
- Tile: `v` vertices as differences from the previous one (north cells, west cells, height in yards), `p` per polygon its
  vertex count, area (1 ground, 2 water, 3 ocean) and vertex indices as differences from the previous index, `x` links to
  the next tile (polygon, edge, direction 1 east / 2 north / 3 west / 4 south, polygon there, edge there), `c` each
  polygon's component.

- Places (`TwichUI.NavDataStore.places[m]`, a record of its own so that a journey passing through a map needn't decode its
  crossing graph): `pl` per place joined to this map, flat: id, tile (x·64 + y), polygon, stand point x·10, y·10, the number of
  attachments, then that many (crossing, cost) pairs; `pw` the walks between places (a, b, weighted yards, a < b).
- `Data/Transit.lua` sets `TwichUI.NavDataStore.transit`: `p` places (id, kind 1 flight point / 2 dock / 3 teleport arrival, map,
  faction 1 Alliance / 2 Horde / 3 both, taxi node), `n` names, `t` town names, `fl` flights (from, to, seconds), `fe` ferries
  (from, to, ride seconds, stay, cycle, kind 1 boat / 2 zeppelin), `tp` teleports (spell, arrival place, cast seconds), `sp` the
  speeds used (yards a second).

World frame: continent yards, x north and y west, as `UnitPosition` and `C_Map.GetWorldPosFromMapPos` give them.
